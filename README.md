# 概要

コミットをすると自動的に`cloudflare-workers-and-pages`ビルドが走る。

短縮URLはShort.ioのCNAME・APIを使用

# 開発メモ

### ブランチ運用ルールについて
[参考サイト](https://cloudsmith.co.jp/blog/efficient/2020/08/1534208.html)

### フローチャート

1. mainというブランチを元に、新しいブランチを作る
2. 必要な変更を加えてファイルを保存します
3. コミット（Gitに対するセーブ）する。コミットする時、メッセージを書くように求められられるので、[コンベンショナルコミット](https://www.conventionalcommits.org/ja/v1.0.0/)という、メッセージの書き方で書く。

### コンベンショナルコミットについてのメモ 

[Conventional Commits](https://marketplace.visualstudio.com/items?itemName=vivaxy.vscode-conventional-commits)という拡張機能を入れると、やりやすい

* メッセージの1行目には変更した点の大まかな内容を書く。
    * 1行目は45文字以内で書くことを推奨。
    * コンベンショナルコミット：1行目は「変更の区分」、半角コロン、半角スペースで始める。
        * `feat: [大まかな内容]`新機能
        * `fix: [大まかな内容]`バグ修正
        * `docs: [大まかな内容]`ドキュメントを変更
        * `style: [大まかな内容]`コードの意味に影響を与えない変更（空白、書式設定、セミコロンの欠落など）
        * `refactor: [大まかな内容]`バグ修正をせず、機能を追加しないコード変更
        * `perf: [大まかな内容]`パフォーマンスを向上させるコード変更
        * `test: [大まかな内容]`不足しているテストの追加または既存のテストの修正
        * `ci: [大まかな内容]`GitHub Actionsを変更
        * `chore: [大まかな内容]`srcまたはテストファイルを変更しないその他の変更
     * 発展的な内容：複数の種別に該当する場合は、引き返して複数のコミットに分割する。
* メッセージの2行目以降は、より詳しい内容を書くことができる。
* メッセージは日本語か英語で。
